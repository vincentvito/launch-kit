# AGENTS.md

Guidance for any AI coding agent (Claude Code, Codex, Cursor, Copilot, etc.) working in this repository.

This is the **ClickStudio standard starter**. Every new ClickStudio app begins here. Stick to the stack and conventions below — do not introduce alternatives without an explicit human approval, even if you can think of "a better way."

---

## The Stack — Do Not Substitute

| Layer | Choice | Notes |
|---|---|---|
| Framework | **Next.js 16** (App Router) | No Pages Router. |
| UI runtime | **React 19** | Server Components by default; `'use client'` only when needed. |
| Language | **TypeScript** (strict) | No plain `.js` source files. |
| Styling | **Tailwind CSS v4** | No CSS modules, styled-components, or emotion. |
| Components | **shadcn/ui** + Radix primitives | Add components with `npx shadcn@latest add <name>`. |
| Icons | **lucide-react** | Don't add another icon library. |
| ORM | **Prisma 7** | Schema in `prisma/schema.prisma`. |
| Database | **Postgres / Supabase** | `DATABASE_URL` is the runtime URL; `DIRECT_URL` is the migration URL. |
| Auth | **better-auth** | With Prisma adapter. Email/password + Google OAuth (optional). |
| i18n | **next-intl** | Cookie-based locale; messages in `messages/<locale>.json`. |
| Lint | **ESLint** with `eslint-config-next` | |

If a task seems to require something off this list, **stop and ask** instead of installing it.

## Project Conventions

- **Pathing:** Use the `@/` alias (see `tsconfig.json`). Never use long relative imports like `../../../lib/x`.
- **Prisma client:** Always import the singleton from `@/lib/prisma`. Don't `new PrismaClient()` anywhere else.
- **Auth:** Server-side, import `auth` from `@/lib/auth`. Client-side, import from `@/lib/auth-client`.
- **Generated Prisma client** lives at `lib/generated/prisma/` and is gitignored. It's regenerated by the `postinstall` script.
- **Translations:** All user-facing strings go through `useTranslations` / `getTranslations`. Add keys to **both** `messages/en.json` and `messages/es.json` — never let one fall behind.
- **Components:** Reusable UI in `components/ui/` (shadcn primitives) and `components/` (app-specific). Page-level UI stays inside `app/`.
- **Server Components by default.** Add `'use client'` only when you need state, effects, or browser APIs.
- **No comments unless the *why* is non-obvious.** No file-header banners, no "// added by agent", no narrating what the code does.

## Startup Contract

A fresh clone needs Supabase/Postgres env vars before booting:

```bash
npm install
cp .env.example .env
npm run dev
```

That means:
- **Postgres is required.** Set `DATABASE_URL` and `DIRECT_URL` in `.env`. For Supabase, use the pooled transaction URL for `DATABASE_URL` and the direct/session URL for `DIRECT_URL`.
- **No login required to view the app.** Landing, changelog, and dashboard render. Login only fails gracefully if Google OAuth isn't configured.
- **Production access controls.** `LAUNCH_KIT_PUBLIC_FREE_ENABLED` controls anonymous free generation, `LAUNCH_KIT_ADMIN_EMAILS` grants manual premium/admin access, `RATE_LIMIT_*` overrides persisted API rate limits, and billing can run in admin-granted manual mode with `BILLING_PROVIDER=manual` plus a strong `BILLING_ADMIN_TOKEN` until Stripe env vars are set.
- **Billing hooks.** Stripe-ready routes use `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, and `STRIPE_PRICE_ID`; manual entitlement updates use `BILLING_ADMIN_TOKEN`.
- **Outbound outreach delivery.** `OUTREACH_EMAIL_WEBHOOK_URL` and `OUTREACH_EMAIL_WEBHOOK_TOKEN` can connect the reviewed outreach flow to a real delivery service. Leave unset to keep no-delivery tracking.
- **`postinstall` runs `prisma generate`** so the generated client is always present after install.
- **`predev`/`prebuild` is folded into `dev`/`build`** as `prisma migrate deploy && next ...` — keeps the configured Postgres database in sync with the schema.

If you change any of these guarantees, update this file and the README in the same PR.

## Database URLs

Use Postgres everywhere:

1. `DATABASE_URL` is used by the app runtime. With Supabase, use the transaction pooler on port `6543` and include `pgbouncer=true&connection_limit=1`.
2. `DIRECT_URL` is used by Prisma migrations. With Supabase, use the direct/session connection on port `5432`.
3. `prisma/schema.prisma` and `prisma/migrations/migration_lock.toml` must stay on `postgresql`.

## When Adding Features

- **Database changes:** edit `prisma/schema.prisma`, then `npx prisma migrate dev --name <change>`. Commit the generated migration file.
- **New page:** add it under `app/`. Use Server Components unless you need client interactivity. Translate all strings.
- **New shadcn component:** `npx shadcn@latest add <name>` — don't hand-roll a primitive.
- **New env var:** add to both `.env.example` (with safe default or empty placeholder) and document it in this file or the README.
- **New dependency:** justify it in your PR description. Prefer using something already in `package.json`.

## Things Not To Do

- Don't add a state-management library — React 19 + server components handle this.
- Don't add an animation library beyond `tw-animate-css`.
- Don't add a form library, validator, or HTTP client unless explicitly approved.
- Don't replace the auth or ORM choice.
- Don't commit `.env`, `prisma/*.db`, or anything in `lib/generated/`.
- Don't write a `CHANGELOG.md` automatically — it's curated.
- Don't add testing frameworks until the project actually needs them; when needed, default to Vitest + Playwright.

---

## Deployment

Default target is **Vercel**. The build command is `npm run build` (which runs `prisma migrate deploy` first). Set `DATABASE_URL`, `DIRECT_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, and `NEXT_PUBLIC_APP_URL` in the Vercel project.
